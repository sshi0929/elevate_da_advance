## Commands

`run_eval_suite.py` re-execs itself under `module_3/.venv`, so plain `python3` works from any
directory — no `uv run`, no manual venv activation.

```bash
python3 tests/eval/run_eval_suite.py                      # full 7-case benchmark
python3 tests/eval/run_eval_suite.py --tier livedata      # one tier
python3 tests/eval/run_eval_suite.py --case UC_1.3_real-time_cashier_metrics

python3 tests/eval/scripts/validate_contracts.py --skip-data   # schema + linkage only
python3 tests/eval/scripts/validate_contracts.py               # + SQL data assertions
python3 tests/eval/scripts/sync_adk_assets.py --check          # CI drift guard
python3 tests/eval/scripts/extract_schemas.py                  # refresh ground truth
python3 tests/eval/scripts/estimate_eval_cost.py               # cost of the last run
```

## Two things worth knowing before you read the config

**1. Grading is split into two tiers.** Five cases read static data and are graded against the
golden answer. Two cases read a **1-hour rolling Cloud Bigtable window**, so any frozen golden
answer expires within the hour — those are graded *reference-free* on faithfulness to the tool
output actually returned, plus rubric-scored tool-use correctness. Applying one metric set to
both groups is what produced the original 0/7 benchmark. Full reasoning in
[§1.1.8 of the report](./evaluation_report.md).

**2. `eval_config.yaml` is authoritative; the ADK JSON is generated.** ADK only reads JSON
criterion files and only discovers eval sets inside `<agents_dir>/<app_name>/`. These four
artifacts are generated by `sync_adk_assets.py` and must not be hand-edited:

| Generated artifact | Consumed by |
| :--- | :--- |
| `module_3/app/eval_config_reference.json` | reference tier grading |
| `module_3/app/eval_config_livedata.json` | livedata tier grading |
| `module_3/app/test_config.json` | bare `adk eval` auto-discovery fallback |
| `module_3/app/cymbal_ops_benchmark.evalset.json` | ADK Dev UI discovery (mirror of `golden-data.json`) |

`run_eval_suite.py` runs the drift check on startup and aborts if any are stale.

> [!WARNING]
> The ADK **Dev UI ignores all `*_config.json` files** — it passes the Run-modal checkboxes
> straight through and has no judge-model field, so UI runs use ADK's obsolete
> `gemini-2.5-flash` default and the wrong metric set for the live-data cases. Use the CLI
> runner for any official scorecard.
